# USA Vision

**Audit any software, at any phase, and tell everything about it.**

USA exists to answer one question completely:

> Given this software — what it claims to do, what it is, what stage it is
> at — what is its state, what is it lacking, what is missing, what must be
> added, which direction decisions are pending, where is the foundation
> failing, and where are the holes?

## What that means in practice

- **Any software, any phase.** Prototype to legacy, any stack. A new repo gets
  foundation readiness; a mature one gets drift, debt, and assurance depth.
- **State, not just findings.** Health, confidence, evidence, trajectory —
  and the vision the project claims, checked against what the tree shows.
- **Lacking, missing, direction-needed.** USA does not only list violations;
  it names absent capabilities, undecided directions, and foundation gaps,
  each with the evidence (or its absence) attached.
- **Find holes, don't exploit them.** USA finds the hole itself — it does not
  penetrate, exploit, or prove exploitability. Penetration testing is an
  explicitly future direction, not a present capability (see
  [What USA is not](USA.md#what-usa-is-not)).
- **Live and conversational.** Auditing becomes a session with the project
  and the developer: interviews, working-environment checks, vision
  alignment — with an LLM where reasoning helps and deterministic checks
  everywhere a claim must be verified.
- **Toward development takeover.** The trajectory is an agent loop that can
  carry software forward, not just grade it: today's judgement queue is
  tomorrow's work queue. The name USA suffices for now; the architecture
  (deterministic spine, agent layer, derived data) is built to outgrow it.

## What it is not (today)

Deterministic, offline, evidence-first. The LLM proposes and interprets; the
engine verifies. No verdict the tool cannot support, no claim without a
file:line, no score from prose. The day USA asserts what it cannot show is
the day it stops being USA.
