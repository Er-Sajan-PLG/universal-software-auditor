# 36. Narrative report is a second format over the same substrate

- **Date:** 2026-09-14
- **Status:** Accepted

## Context

The deterministic checklist (ADR-0004/0018) is excellent as a machine record
and a poor human report. A seven-part review of the `demo-app` output converged
on the same verdict in different words: the report leads with a number, buries
the foundation, prints 10/10 for unexamined sections, launders downgrades into
an empty sprint, lists findings instead of reading them together, and never
gives a verdict. The engine's _evidence_ was never the problem; the
_presentation_ was.

Two naive designs were rejected. First, replacing the checklist wholesale —
that would break `usa diff`, JSON/SARIF consumers, and every audit team that
already trusts the section scorecard. Second, hand-authoring a "better sample"
in the docs — a generated sample is machine-checked by `docs:sample` (ADR-0020);
a hand-written one would immediately drift and would no longer be _this_ audit's
output.

## Decision

**A narrative renderer ships as a second format (`--format narrative`) that
consumes the same `AuditReport` as the checklist.**

- `src/report/narrative.ts` derives, never authors: verdict first, foundation
  gate, fires composed into one trust-boundary failure, severity downgrades
  disclosed (safety vs process), honest scoring, a dependency-aware roadmap,
  and the machine record buried at the bottom. Deterministic — no `Date.now()`,
  no roaming prose that could disagree with the trailer.
- The verdict is derived from the worst open finding, not a number. Sections
  under 40% confidence render "INSUFFICIENT EVIDENCE" instead of a score; a
  null-scored section renders "NOT ASSESSED". A 10/10 at 25% confidence is a
  2.5 of an unknown 10.
- The roadmap buckets by _declared_ severity, not the dampened one — so a
  HIGH the profile pushed to MEDIUM still appears in "this week", never in an
  empty sprint that the downgrade manufactured.
- The trailer (`usa-report-v1`) is embedded unchanged, so `usa diff` and
  `parseTrailer` keep working on narrative output.
- `examples/sample-report.md` is regenerated by the narrative renderer, so the
  canonical sample demonstrates the human format instead of the checklist.

## Rationale

1. **Substrate stays single.** One `AuditReport`, four projections (md,
   narrative, json, sarif). Nothing can disagree with the trailer because
   everything reads the same object.
2. **Honesty is enforceable, not aspirational.** "Never print a score under
   thin evidence" is a testable invariant now, not a review comment.
3. **No drift.** The narrative is generated, so `docs:sample` keeps it honest;
   the checklist remains the fallback for teams that want the raw table.

## Consequences

**Good:** the report humans actually read answers the reviews' three charges —
verdict, foundation gate, honest confidence — while every machine consumer is
unchanged. The sample now shows the better story.

**Bad:** a second format is a second surface to keep deterministic; the
narrative must re-derive anything the checklist already computes (it does,
off `MaturityProfile` and `Finding.baseSeverity`). Its "voids" and "not
audited" sections are static prose about the _method_, deliberately — they are
checked into the renderer, not derived per-target.

**Neutral:** `md` remains the default; `narrative` is opt-in until it earns
the default slot. Either can graduate to default later without repaving the
substrate.
